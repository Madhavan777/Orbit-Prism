01 · The bottleneck in numbers

Each pass carries 19.2 MB, so the satellite must choose.

A 256 kbit/s link open for ten minutes moves 19.2 MB, and one gigabyte would need about 52 passes. Meanwhile, conventional Earth observation satellites waste link bandwidth transmitting cloud-obscured or non-critical frames while urgent disaster perimeters wait in flash memory. We read this as a choice problem, not only a compression problem: decide what goes first, and state honestly how many critical tiles might be missed.

19.2 MB

Pass transmission budget

Total data a LEO satellite can downlink across a 10-minute ground station window at 256 kbit/s.

52 Passes

Per gigabyte needed

Without on-device triage, transmitting an uncompressed sensor swath takes days across multiple orbital passes.

4.2 MB

Onboard SRAM ceiling

Strict physical memory limit. Entire chips (6.8 MB) cannot fit; inference must run tile-by-tile in INT8.

4.8×

Faster critical alert

Priority L0/L2 scheduling transmits validated flood perimeters to emergency operators in under 90 seconds.

    06 · Evaluation defense

    Questions judges ask.

    Plain, direct answers without numbers that do not come directly from the tested API.

    Is this just cloud detection?
    No: cloud detection is one input; the contribution is the calibrated miss rate, the radar fallback and the byte-budget scheduler, measured together.
    Why tiles, not pixels?
    A full chip does not fit in memory; tiles are enough to decide what to send.
    Why a small CNN over a water index?
    A colour-index baseline is one of our comparisons; if the CNN does not beat it we say so.
    How does it fit in 4.2 MB?
    One tile at a time, INT8 weights, peak activation estimated from the model graph; see the memory table.
    What if radar is wrong?
    Radar can false-alarm on smooth surfaces; uncertain tiles would go as previews; we report false alarms.
    What if the cloud check is wrong?
    We report its error separately.
    Does the promise hold under data shift?
    Only if test data resembles calibration data; we report the miss rate we actually get on a held-out event.
    Do optical and radar come from one satellite?
    No, Sentinel-2 and Sentinel-1, so the paired payload is simulated.
    Is this real hardware?
    No, a simulation with measured and estimated memory.
    Why only floods?
    Floods are the worked example; fire data is not loaded yet.
    07 · Technical definitions

    Glossary.

    Key terms and conventions used throughout ORBIT-PRISM.

    Tile

    A 128×128 pixel sub-image (65,536 B optical, 32,768 B radar). The fundamental atom of onboard triage and scheduling.

    Chip

    Original 512×512 pixel satellite scene, partitioned into a 4×4 grid of 16 tiles to fit inside the 4.2 MB SRAM limit.

    Critical Tile

    A tile where flood water covers at least 30% of valid pixels (water_frac ≥ 0.30). Priority targets for downlink.

    Miss-Rate Dial (α)

    Conformal threshold dial (α ∈ {1%, 5%, 10%}) setting the maximum allowable probability of missing critical flood tiles.

    Scaled Pass

    Transmission budget scaled to exactly 20% of the selection's data (~3.03 MB for Bolivia), not the full 19.2 MB orbital pass.

    L0 / L1 / L2 Layers

    Downlink telemetry tiers: L0 (32-byte alert packet), L1 (preview / buffer sub-swath), L2 (full critical flood tile).

    Priority Score

    Ranking metric computed as flood probability × flood extent (p_flood × extent) to order the queue.

    Held-Out Event

    Geographic disaster event (Bolivia in Sen1Floods11) strictly held out from training and calibration to measure distribution shift.

    Simulated Cloud

    Synthetic cloud masks generated for controlled cloud-penetration experiments (Sen1Floods11 contains no native cloud masks).

    SRAM

    Onboard satellite static RAM ceiling (strictly constrained to 4.2 MB), precluding full-scene processing.

    INT8

    8-bit integer quantization used to compress model weights and activations for low-power onboard inference.

    08 · Project boundaries

    Honest limits.

    • A simulation of the link and memory limits, not flight hardware. Nothing here is an on-orbit claim.
    • Clouds are simulated; Sen1Floods11 has no cloud mask. Results are from the held-out Bolivia event and one training run.
    • The miss-rate promise holds only when test data resembles the calibration data. We report the miss rate actually achieved. With few critical tiles the 1% target cannot be met exactly, so it falls back to sending everything.
    • Floods are the worked example. Forest-fire data is not loaded yet. Tiling, cloud filtering and confidence thresholds are not new; the contribution is combining them inside 4.2 MB and measuring honestly.
    • Imagery: contains modified Copernicus Sentinel data. Dataset: Sen1Floods11 (Bonafilia et al., CVPR Workshops 2020); its licence is unconfirmed.
